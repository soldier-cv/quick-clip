## 一、 产品定位与核心价值观

### 1.1 产品定义
QuickClip 是一款专为 Windows 平台打造的**极速、纯粹、高可靠的本地剪贴板生产力工具**。

### 1.2 核心理念
1. **纯本地离线，绝不触碰云端**：
   - 剪贴板属于最高级别的个人与企业隐私通道（包含账号、密码、密钥、身份证、通讯录、商业机密等）。
   - QuickClip 坚决不设账号系统，不向任何云端上传用户剪贴数据，数据 100% 持久化在用户本地 SQLite。
   - **关于多端同步的解耦美学**：成熟输入法（如微信输入法、搜狗输入法）与操作系统互联已将跨端传输做到极致，其跨端同步最终通过 Win32 API 写入本机剪贴板。QuickClip 专注于通过底层事件捕获本机剪贴板，无需重复造轮子，既实现多端打通，又守住本地隐私底线。
2. **极速响应，无感打扰**：
   - 启动、唤起、检索、粘贴必须在毫秒内完成。开机自启通过后台静默预热，杜绝首次冷卡顿。
3. **忠实还原，绝不篡改**：
   - 剪贴板管理器的神圣天职是**“忠实记录、原样还原”**。严禁自作聪明地做任何文本“猜测与自动矫正”，绝不破坏用户的代码、多语言字符或特殊格式。

## 二、 不可侵犯的系统护栏 (Inviolable Guardrails)

在后续的任何代码改动中，必须恪守以下**六大红线**：

1. 🔴 **严禁破坏既有功能**：
   - 新增功能或优化性能时，必须保证全量现有功能不受影响。若遇冲突，应设计优雅的协同机制，绝不能通过“砍掉旧功能”来逃避技术难点。
2. 🔴 **严禁篡改剪贴板原始数据**：
   - 复制的数据必须原汁原味入库并原汁原味粘贴。严禁加入任何未经用户明确授权的“智能转码 / 乱码猜测修复”，防止破坏正常 Base64、多语言符号或二进制文本。
3. 🔴 **严禁污染系统剪贴板**：
   - 捕获阶段只读系统剪贴板（`Capture` 只读不写）。只有当用户主动触发“粘贴”或“复制”时才允许覆盖系统剪贴板。
   - 用户主动暂停捕获或复制敏感内容时，不得有任何隐式写盘行为。
4. 🔴 **严禁违背 Windows 线程与焦点模型**：
   - 所有窗口激活、焦点转交、UI 动画必须严格在 UI 主线程执行；所有剪贴板 I/O、图片编码、网络调用、数据库读写必须在后台 STA 线程或线程池执行，互不阻塞。
5. 🔴 **文案克制与交互减负**：
   - 界面文案必须精炼专业，严禁堆砌技术实现细节（如“免密直连”、“延迟毫秒”等冗余词）。
6. 🔴 **严格遵循安全与发版规范**：
   - 保持双渠道发版同步（GitHub + 国内 Gitee 镜像优先）；严格遵循环境安全准则。

## 四、 各模块详细功能与需求规格说明

### 4.1 剪贴板监听与原生接管体系
- **Win32 原生调用**：
  - 弃用 WPF/OLE Clipboard API（防止目标程序卡死时拖死 QuickClip）。使用 `OpenClipboard`、`GetClipboardData`、`SetClipboardData`，并在打开失败时做毫秒级短重试与占用进程日志追踪。
  - 支持 `CF_UNICODETEXT`、`CF_TEXT`、`CF_HDROP`（文件列表）、`CF_DIB` / `CF_DIBV5`（高保真位图）以及自定义注册格式 `PNG`、`HTML Format`、`Rich Text Format`。
- **Win+V 底层键盘钩子**：
  - 通过低级键盘钩子（`WH_KEYBOARD_LL`）精准拦截 `Win + V`，阻止 Windows 开始菜单误弹与原生剪贴板竞争。
- **状态快照与接管自愈**：
  - 启动时自动快照用户原本的注册表状态（Windows 剪贴板历史启用状态与热键禁用项）；
  - 当在设置中关闭接管、正常退出或卸载时，100% 原样还原系统初始状态，不破坏系统原生功能。
- **开机自启静默预热**：
  - 开机后台自启动时，在离屏区域（-32000, -32000）静默完成 WPF 视觉树测量、样式解析与 JIT 编译，确保用户首次按下 `Win + V` 毫秒级闪现。
  - 配备 450ms 唤起防连击保护，防止用户连按导致刚唤起立刻被关。

### 4.2 剪贴历史与卡片管理
- **本地存储与生命周期**：
  - 采用 SQLite（`quickclip.db`）存储，支持条数上限（如 100/500/1000 条）自动滚动淘汰。
  - 置顶项（`is_pinned = 1`）受保护，不受最大条数淘汰影响。
  - 条目删除时，自动联动清理本地磁盘上的缩略图文件（`previews/`），杜绝磁盘垃圾堆积。
- **防抖与自身回写过滤**：
  - 严格记录写入剪贴板时的序列号（`CurrentSequence`）。只有序列号完全一致的自身写入才被忽略，用户在 2 秒内的真实外部复制绝不误丢。
- **检索体系**：
  - 支持纯文本、链接、文件名称的多字段模糊匹配。
  - 集成拼音首字母引擎（`ChnCharInfo`），支持中文首字母快速定位（如 `gys` 匹配 `供应商`）。

### 4.3 粘贴注入与目标窗口交互体系
- **目标窗口（TargetWindow）追踪**：
  - 无论在普通模式还是置顶模式下，必须精准追踪用户唤起前正在编辑的真实外部程序（如 Notepad++、VSCode、微信、浏览器），严格过滤桌面（Progman/WorkerW）、任务栏（Shell_TrayWnd）以及 QuickClip 自身所有子窗口。
- **三种粘贴通道**：
  1. **普通粘贴（Enter / 双击 / 1~9）**：写入系统剪贴板（若有 HTML/RTF 一并写入），注入 `Ctrl + V`。
  2. **强制纯文本粘贴（Shift + Enter）**：仅写入纯文本，剥离所有富文本格式。
  3. **剪贴板纯文本回贴（全局 Ctrl + Shift + V）**：在任意外部软件中按下，自动提取当前剪贴板纯文本直接粘贴；若是文件列表则自动转为文件名文本粘贴，粘贴完成后还原剪贴板文件对象。
- **连续粘贴模式**：
  - 开启后按 Enter 粘贴完成不隐藏面板，并保持当前选中项，留出微小缓冲夺回主面板焦点，供用户按方向键继续点选下一次粘贴。

### 4.4 连续粘贴栈模式 (收集栈)
- **业务场景**：
  - 针对财务对账、表单逐项录入、多字段跨系统迁移等需要连续复制 10 个数据、再连续粘贴 10 次的场景。
- **核心逻辑**：
  - **显式开关**：默认关闭。通过全局快捷键（默认 `Ctrl + Shift + S`）或标题栏按钮开启/关闭。
  - **FIFO 先进先出队列**：开启期间，用户在外部的每次复制自动压入栈底。
  - **多行文本一键拆分**：支持将剪贴板中多行数据按换行符拆分成独立条目并顺序压栈。
  - **物理 Ctrl+V 逐项出栈**：在外部目标窗口按 `Ctrl + V` 时，底层钩子拦截并按顺序出栈一项粘贴，直到栈空自动退出。
  - **桌面迷你 HUD**：屏幕角落浮动微型指示器，显示剩余项数、下一项预览，并提供快速清空与退出按钮。

### 4.5 常用短语库与动态模板引擎
- **分类收纳与管理**：
  - 独立 Tab 页，支持用户自定义分类（通用、代码、办公、回复等）。
  - 支持新建、编辑、删除短语。
- **动态占位符引擎 (不区分大小写)**：
  - 日期时间：`{date}`、`{time}`、`{datetime}`、`{year}`、`{month}`、`{day}`、`{weekday}`、`{week}`
  - 时间戳：`{timestamp}`（10位）、`{timestamp_ms}`（13位）
  - 唯一标识：`{guid}` / `{uuid}`（标准）、`{guid_n}`（无连字符）
  - 设备与用户：`{username}` / `{user}`、`{computername}` / `{device}`
  - 随机数与剪贴板：`{random4}`、`{random6}`、`{clipboard}`
- **微调填入 (Snippet Quick Adjust)**：
  - 点击微调按钮弹出轻量微调窗，保留动态占位符与原始模版。
  - 用户可在粘贴前就地临时追加或微调参数，按 `Ctrl + Enter` 一键替换占位符并直接注入目标窗口。
  - 原始短语模版不受影响，无需为了单次修改而重复新建短语。

### 4.6 桌面贴图置顶系统
- **业务场景**：
  - 类似 Snipaste，将参考截图、设计草图、表格截图钉在桌面上方供对比参考。
- **核心交互**：
  - 点击卡片「贴图置顶」按钮或右键菜单触发，无边框展示原图。
  - **按住任意位置拖拽**平滑移动位置。
  - **鼠标滚轮**实现 20% ~ 400% 无级缩放。
  - **Ctrl + 鼠标滚轮**实现 20% ~ 100% 透明度渐变。
  - **右键菜单**：复制、另存为、100% 原始尺寸还原、置顶切换、关闭。
  - **极速关闭**：双击图片或按 `Esc` 立即关闭。

### 4.7 二维码双向解析与生成
- **电脑到手机（生成）**：
  - 任何文本或链接卡片，悬停二维码图标即可弹出高清二维码，手机扫码即可直接获取。
- **手机到电脑（识别）**：
  - 剪贴板中出现任何含二维码的截图或图片时，后台自动异步识别并提取解码内容。
  - 卡片呈现高亮二维码徽章，悬停可查看解析文本，支持一键复制。
  - 支持直接**双击二维码预览色块**，自动将识别内容复制并立即粘贴到前台目标窗口。

### 4.8 OCR 文字识别与大模型视觉整合
- **双模架构**：
  - **离线模式**：Windows 原生 OCR 或本地 PP-OCRv6，无需联网，速度飞快。
  - **视觉大模型模式**：支持配置兼容 OpenAI / Ollama / 魔搭 等视觉大模型端点（如 Qwen-VL、GPT-4o 等），支持结构化排版（Markdown 表格、空间键值对识别）。
- **可编辑与防误丢机制**：
  - 识别弹窗内的文本框允许用户**直接原位编辑纠错**；
  - 纠错后点击「复制」即复制修改后的内容；
  - 若内容已被修改，按 `Esc` 或点关闭时会弹出二次确认，防止手滑丢失修改劳动成果。

### 4.9 智能多语种文本翻译
- **场景与交互**：
  - 历史卡片点击「翻译」按钮，直接向下平滑展开抽屉式译文面板。
  - 自动识别源语言（中文自动翻英文，外文自动翻中文）。
  - 提供一键「复制译文」与「直接粘贴（替换目标内容）」。
- **降级机制**：
  - 优先使用用户在设置中配置的大模型翻译，未配置时自动无缝降级到微软/Google 免密公共通道。

### 4.10 全局与面板热键系统
- **键位支持与冲突自愈**：
  - 支持全量常用功能自由配置全局热键或面板内快捷键。
  - 当热键被其他软件占用时，具备安全提示与自愈机制。
- **输入穿透与焦点守护**：
  - 当搜索框处于聚焦状态时，`↑` / `↓` 方向键通过 PreviewKeyDown 隧道提前拦截，优先控制列表项上下选择，输入字母则正常进入搜索框。

### 4.11 主题、渲染与工程健壮性
- **多套 Fluent 主题**：
  - 内置 Terminal 终端灰黑、One Dark、GitHub Dark、GitHub Light、Nord 等主题，随心切换。
- **DPI 与远程环境渲染降级**：
  - 检测到远程桌面（RDP）或特殊虚拟显卡驱动（如 OrayIddDriver）时，自动启用软件渲染降级，防止远程桌面下黑屏或整屏闪烁。
- **日志防膨胀滚动机制**：
  - 本地诊断日志（`debug.log`）大小限制在 2MB，并按 `.1`、`.2` 滚动保留，严禁无限制膨胀挤占用户磁盘。
- **更新渠道与双镜像**：
  - 检查更新策略为**国内 Gitee 通道优先，GitHub 备用降级**，确保国内用户秒级响应与平滑升级。

## 五、 交互行为与文案规范

1. **文案精炼原则**：
   - 按钮与菜单文案统一简明直观：使用「粘贴」而非「应用并粘贴」；使用「保存」而非「保存修改」；使用「复制」而非「仅复制」；使用「贴图置顶」而非「贴图到桌面前端」。
   - 下拉选项不得包含冗余实现描述：统一为「微软翻译」、「Google 翻译」、「AI 模型翻译」。
2. **操作保护原则**：
   - 鼠标双击列表粘贴时，必须排空鼠标按键消息，严禁让鼠标释放事件（`WM_LBUTTONUP`）穿透到底层网页或软件链接上导致误点。
   - 连续粘贴模式下，粘贴完成不得强制将光标移到下一项，应由用户自主选择是否下移，防止破坏多次连续重复粘贴场景。

## 六、 开发避坑指南与反模式 (Anti-Patterns)

1. ❌ **反模式 1：在后台线程调用 `SetForegroundWindow`**
   - **后果**：Windows 前台锁会坚决拦截，导致目标外部窗口无法被激活，随后 Ctrl+V 注入失败。
   - **正确做法**：凡是涉及把焦点转交给外部目标程序的动作，必须在 UI 主线程（Thread 1）中执行。
2. ❌ **反模式 2：依赖不可靠的 `WM_ACTIVATE` 寻找外部窗口**
   - **后果**：当 QuickClip 置顶时，从外部点击 QuickClip 时 `lParam` 经常为 0，顺着 Z 序盲目查找极易把桌面或任务栏（`explorer.exe`）误记为目标。
   - **正确做法**：采用全局前台监听或规范的外部窗口跟踪机制。
3. ❌ **反模式 3：对剪贴板数据做主观猜测与矫正**
   - **后果**：误伤正常数据，造成不可逆破坏。
   - **正确做法**：原汁原味入库、原汁原味提取。
4. ❌ **反模式 4：为了修一个模式改坏另一个模式**
   - **后果**：例如为了修置顶模式导致普通模式下窗口关不掉，或为了修连续粘贴导致单次粘贴失效。
   - **正确做法**：每次修改必须在**普通模式（唤起即粘、粘后即藏）**与**置顶模式（常驻便签、连续交互）**两种场景下分别回归验证。
